# BS5 curriculum pilot v1 — fixed schedule and Kaggle handoff

This is a new experiment, independent of the historical A/B runs. Target
physics, six BS coordinates (only BS index5 failed), R6 one-hop router v2,
90 UE × 4 Mbps, launch B, charging stations, 150-slot episodes, reward and
111/116 state/observation remain those of the audited target. Networks keep
five agent slots and ten Cartesian outputs. No shaping, prior checkpoint,
macro-actions, teacher actions or oracle labels enter the learner.

## Locked experiment

Machine-readable source: `configs/bs5_curriculum_fixed_v1.json`.
Four scratch arms C-R/D-R/C-N/D-N × fresh training seeds 551/552 × 24k
TOTAL steps = 192k. R allows Relay; N masks odd actions in acting AND
collection-time bootstrap masks. Same initial weights per training seed;
optimizers, exploration and replay are independent. Historical A/B is context,
not a substitute for fresh direct controls. Seeds were checked against local
protocol manifests before reserving them; this is not a claim about remote runs.

| Stage | Total steps | Active UAVs | Starts/movement | UE motion | Energy |
|---|---|---:|---|---|---|
| S1 | 0–3k | 2, shuffled IDs/position assignment | (19,16)/(16,11), Stay only | frozen | frozen |

Intervals are left-closed/right-open. Changes happen only between complete
episodes. Starts change at reset, never by a controller during rollout. The
full-task evaluation always uses target conditions, from checkpoint step0.

The training wrapper explicitly parks absent IDs with status3; they cannot
serve, relay, collide, charge or reactivate. The existing three status bits
are all zero for this unavailable state; slot IDs/layout do not change.
Raw logs carry `active_ids` and the explicit status code. Energy freezing
sets drain/charging/return thresholds to zero during the step while retaining
real reset battery values. The target battery-cycle flag stays enabled:
using its historical false setting would reactivate every agent. A display
hook in the base environment is the only shared extension; its physical step
logic is unchanged and full-target parity is tested through 150 slots.

## Pools and diagnostic gates

Full-task train: 120001..120040. Full-task validation: 130001..130010,
already inspected development validation, never an unseen final test.
S1/S2 train: ALL fixture scenarios 140001..140010; stage-validation:
170001..170010. Preflight enumerates every two-agent role assignment on the
whole fixture and stage-validation pools and writes every case, including
zero/negative relay benefit. There is no positive-case filtering.

Assignment/reset/exploration/replay/evaluation streams are separate. Active
IDs are permuted using a separate setup RNG, leaving target UE and residual
draws unchanged. Each global episode has a frozen full-task scenario,
fixture scenario, residual battery Uniform[24,36], assignment seed. Full eval
uses battery30 and scenario-matched residual ID. Different training tasks are
paired only when physical conditions match; full eval hashes must always match.

Gates NEVER alter the fixed schedule. S1 records net role attainment relative
to all-Access and the exact feasible role optimum at the same static geometry.
Positive-gain cases use (U−U_all_access)/(U_opt−U_all_access), tolerance1e-6;
nonpositive cases stay in the evidence and are explicitly ineligible for that
ratio. Threshold: ≥0.5 in ≥80% eligible episodes; consecutive passes are logged.
For N use U/U_opt in its own feasible action space. S1-N is structurally a
one-action task; a pass does not prove learning. S2 held-out starts use a
diagonal joint perturbation not generated by the axial training jitter;
movement restoration requires actual movement and utility > initial feasible
role optimum +0.005. Preflight publishes a legal three-step witness for S2a.
S2 `gate_failed` uses movement restoration in at least 80% of all stage-validation
episodes; its role-attainment diagnostic is also retained.
All ineligible cases and gate failures are reported, not removed. S3 gates
are role/transfer diagnostics, not evidence that full-task transfer succeeded.
S1 retention is probed at 6k/12k/24k; full-task curves measure transfer.

## Replay, optimization, boundaries

At every physical condition change, clear replay and start a logged lineage.
Keep online/target weights, Adam, LR, global update/sync counters and global
epsilon schedule (1→0.05 over18k). Warmup is still the source rule:
buffer size ≥max(1000,64), so each clear delays learning. D arms have no task
changes and no such clears. S3d→S4 changes the label only, not the task;
replay is retained there. Logs count actual updates and discarded transitions.
This is the combined method **curriculum + replay reset**, not an isolated
causal test of curriculum alone. Replay reset/exploration alternatives require
separately named ablations, not retrospective parameter changes.

Replay transitions store current mask, NEXT mask collected before any reset,
stage/substage, collection step and lineage. Source horizon convention is
preserved: time-limit termination sets done=1; no bootstrap crosses reset or
a condition change. Batch targets use each transition's stored next mask.

Common full eval: step0, every3k, and24k (nine opportunities per arm).
Additional full eval/checkpoint at4.5k/7.5k/10.5k is diagnostic only, for ALL
arms. Best is maximum common-cadence mean utility, including0, earlier exact
tie. Tail mean is18k/21k/24k; peak-to-last and normalized common-curve AUC
are reported. Gates never create additional best-selection opportunities.

## Evidence and offline analysis

Each train episode and gradient update is saved. Every eval slot, including
step0, has service-phase geometry/rates/actions/current+next masks/availability,
Q summaries, shadow per-UE rates, sampled role enumeration (slot1/76), residual
identity, exogenous hashes and post-step state. Pure diagnostics never supply
actions/labels/reward. Train trace sampling is frozen: first scenario per
substage, first after boundary, and every10 episodes, with capture reasons.
Immutable per-episode atomic event packets record task changes, replay lineage,
gate failures and evaluation commits. Uncommitted packets are preserved under
aborted_attempts on resume; completed evidence has no duplicated steps.

Metrics: positive-service UE (>1e-12 Mbps), full-QoS UE (≥demand−1e-9), Jain
of episode-mean per-UE rates, first-service/censoring, lifecycle, availability,
relay-required rates, role switches, empty Relay UAV-slots / all active Relay
UAV-slots (null if denominator0), corrected route/opportunity/net gain, sampled
oracle headroom/coverage. Demand-capped throughput =360×utility: these are
not independent benefits. Uncapped delivered throughput is NOT inferred from
capped rates. `uncapped_throughput` is explicitly unavailable in the schema.

`audit_light.zip` includes all committed evidence, protocol/source-hash inventory,
config/schema, preflight, derived tables/plots/report, hashes and standalone
stdlib analyzer. No checkpoint/torch/environment/network is needed:

```powershell
python -B -m scripts.analysis.analyze_bs5_curriculum_bundle --bundle PATH/audit_light.zip --output DIFFERENT_OUTPUT --require-complete
```

Inside an extracted bundle:

```bash
python -B analyze_bundle.py --root . --output ../rebuilt --require-complete
```

Outputs must be outside the extracted evidence root. Integrity checks cover
all files, scenarios/slots, rates/reward, masks, inactive exclusion, pairing,
sample coverage, gates, replay/update/stage accounting, best selection and
trace-derived summaries (relative/absolute tolerance1e-10).
`repro_full.zip` adds source snapshot, weights at committed eval/boundaries,
and latest resume state with weights/Adam/replay/all RNG. Only latest
`resume.pt` is resumable; earlier weights are inference-only. An interrupted
episode is rerun from the latest committed boundary, not its last slot.

## Running and smoke

Use [the Kaggle notebook](../notebooks/bs5_curriculum_kaggle.ipynb) or
[four copyable cells](../notebooks/README_bs5_curriculum_kaggle.md). Kaggle
extracts the uploaded source ZIP; no source copy/unzip cell is needed.
Preparation runs preflight, then a separate debug matrix (8×384=3,072 train
steps, horizon6, all stages/boundaries), exports it and tests standalone analysis
with torch/src blocked and checkpoints absent. The main registry stays prepared
with zero main steps. Fixed main budgets NEVER automatically shrink.

```powershell
python -B -m scripts.training.run_bs5_curriculum_pilot --prepare --outdir results/bs5_curriculum_fixed_20261023
python -B -m scripts.training.run_bs5_curriculum_pilot --run --resume --outdir results/bs5_curriculum_fixed_20261023
```

GPU/CPU config overrides must be written outside the read-only Dataset BEFORE
preparation; source/config fingerprints must stay unchanged for resume.
Smoke runtime includes full traces/shadow/oracle and is extrapolated for main
train/eval counts with a safety factor. It is not a Kaggle runtime guarantee.
Full pilot runs are intended for the user's Kaggle session; local handoff runs
bounded smoke/tests only. Two seeds support pilot observations, not significance.
